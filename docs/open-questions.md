## Provisional implementation choices (flagged for review)

- Matching skips the 8 s agent wait when no agent has polled in the last 10 s, so results arrive in under 5 s (A5) when the agent is offline.
- Experience values extracted include `experienced` (3+ years) so senior roles are filtered out when a new-grad level is selected; the filter offers the three designed levels.
- Generic "Software Engineer" titles count as adjacent to Full Stack Developer; "Data Scientist" and "Applied Scientist" as adjacent to ML Engineer.
- Default font is the system sans-serif (brief); the designs' Public Sans was not bundled.
- Push-to-talk is shown whenever signed in (designs); the "Voice control" preference is stored for suggestions and the profile checklist.
- Accommodation forms (2026-10-24): detected by rules in `convex/ingest/accommodationForm.ts` from listing HTML (form hosts such as forms.gle, or link text/path saying form or request, inside a paragraph about accommodations). Mailto addresses and policy pages are ignored. Matched jobs with a form come first, then by score (changed from a 10-point boost on 2026-10-24: most form jobs are general Software Engineer or ML roles that scored too low to surface); `matches.list` takes `hasForm` to show only them. PROVISIONAL: the Apify path only detects forms if the Actor returns `description_html`; `scripts/build-seed.sh` uses the direct path.
- Accommodation filter (2026-10-24): "Only show jobs that state all my required accommodations" is replaced by "Hide jobs that conflict with my required accommodations" (`matches.list` arg `statesAllRequired` → `hideConflicts`); the strict version hid almost everything because most listings are silent. `jobs.get` returns `accommodationContact { quote, email? }` or null.
- The "Hold to talk" keyboard shortcut and mode are saved per device (local storage), not in the profile: keyboards differ between devices, and it avoids a change to `vInterface`.
- Contract additions (2026-10-24, QA fixes): optional `fullName` on profiles and `profiles.save` (omitted keeps the saved name, "" removes it); drafted emails replace `[Your name]` with it in code after any Claude call; new `emails.clear` mutation (owner-checked) empties a draft and resets approval. Optional `accommodationForm { url, quote }` on jobs, returned by `jobs.get` and in `matches.list` items (`job.accommodationForm`, null when none); `ingest/run:run` takes `direct`; `seed:exportSnapshot` takes `since`.
- Contract additions: `STT_UNAVAILABLE` error code, `voiceReader` interface preference, `note`/`contradicts` on `AccommodationInfo`, `experienceLevel` on jobs, `matches.list` takes `workSetup` (remote | onsite | any) instead of `remoteOnly`, `account.deleteAll` is a mutation (atomic) rather than an action.
- Accommodation emails (2026-10-24, `feat/jobs-accommodation-email`, **for Chris to review**): new optional `accommodationEmail` on jobs (`convex/schema.ts`: `status` verified | unverified | not_found | failed, `emails[{ email, status, evidence[] }]`, `source: "listing"`, `method`, `checkedAt`, `contentHash`), returned by `jobs.get` and in `matches.list` items. Detected by rules in `convex/lib/accommodationContact.ts` (`findAccommodationEmails`) from the stored listing text. "verified" means the listing's own sentence ties the address to accommodation requests; it is evidence from the listing, not independent confirmation, and nothing is ever sent to an address. Stored by `ingest/run:upsertBatch` and `seed:demo`, rechecked when `contentHash` or the detector version changes; reads recompute when the stored result is missing or stale. New `jobs:refreshAccommodationEmails` (internal) backfills. Ranking: a job with a form **or** a verified address comes first (one boost, not two); the `hasForm` filter is unchanged. The shared address pattern no longer accepts a bare "@" with spaces, which had produced `from@airbnb.com` from Airbnb's scam notice. PROVISIONAL: addresses only behind link text (a `mailto:` link that does not show the address) are not in the stored text, so they are not detected.
